# Addendum: rule v2 and query fallback (v2, `rule_v2_exact_anydate`) vs v1 (`rule_exact_anydate`)

Generated by `scripts/13_compare_versions.py --addendum`. Setting: fixed all-mpnet-base-v2 retriever, shared top-1000 pool, rule labels, exact-entity ATC, extended date parser, lambda1 = lambda2 = 0.8; MultiTQ test, 54,584 questions.

**What changed.** (1) Query fallback: TimeR4 rewrites that are empty or truncated are replaced by the original question (`questions_v2.json`, field `query`); search, labels, reranking cues and LLM-free Hit@1 read it. Only those rows were re-encoded and re-searched; every other row of `q_emb_v2.npy` / `top1000_v2_*.npy` equals v1. (2) Answer-slot rule v2 (`tear/labeling/rules.py`, default; v1 kept as `--rule_version v1`) with five fixes from two human checks of the labels: (a) do-support counts only right after the wh-phrase, so a trailing "... before Cambodia did" no longer makes the answer an object; (b) "in" joins the prepositions before the wh-word; (c) "the last country with which / to which / that X ..." -> object; (d) a leading date clause with a comma inside the date ("After Sep, 2011, ...") is removed whole; (e) "suffer(ed) from" asks for the victim -> object, while "made X suffer" still asks for the attacker. (3) Date parser v2 (`--date_parser v2`, `tear/temporal.py`): before/after dates written with a month abbreviation or punctuation ('Sep, 2011', 'Sept. 2011', 'Sep 5, 2011', '5 Sep 2011') are now read; boundaries unchanged (before a month -> its 1st, after a month -> its last day, a year alone -> Jan 1 / Dec 31). The parser is shared by every reranker that uses dates (TimeR4-style, hard window, TR, TEAR, TEAR + window); v1 runs keep parser v1.
